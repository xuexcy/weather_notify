# 数据源

## 只接和风天气

本项目只使用[和风天气](https://dev.qweather.com/)作为数据源，没有备用源：

| 能力 | 和风 |
|---|---|
| 凭据 | API Host + 项目 ID + JWT 凭据（Ed25519 私钥） |
| 官方灾害预警 | ✅ |
| 生活指数 | ✅ |
| 空气质量 | 国标 AQI（`indexes[]` 里优先取 `cn` 开头的那项） |
| 逐小时 / 逐日 | ✅（逐日 3/7/10/15/30 天） |

**没有配置和风时**：`/api/weather` 返回 `need_setup: true` 和一句引导，首页显示
「还没配置和风天气」+「去设置页」，不去请求任何外部接口。

**配置了但请求失败**（网络断开、401、限流、订阅权限不足……）：错误原样返回并显示在首页，
不会再换成别的数据源——兜底源拿不到官方预警，还常把真正的错误盖住。

推送（`src/main.py`）同样只走和风：拿不到数据就不发，宁可不发也不发残缺消息。

> 和风的 `/v7/air/now` 与 `/v7/warning/now` 已于 2025 年废弃（返回 403 Deprecated），
> 本项目改用新版 `/airquality/v1/current/{lat}/{lon}` 与 `/weatheralert/v1/current/{lat}/{lon}`。
> 这两个接口只收经纬度，所以**城市必须是「经度,纬度」或已定位**（IP 自动定位就会写成这种形式）；
> 若城市填的是城市名 / LocationID，实况与预报照常，但空气质量与预警会跳过并记日志。

AQI 标准与分级细节见 [air-quality.md](air-quality.md)。

## IP 自动定位

首次启动时，若 `config.location` 为空，会并发查询多个定位源并写入配置：

| 源 | 作用 |
|---|---|
| ip-api.com | 经纬度 + 中文省名（免费版走 http） |
| ipwho.is | 经纬度 + 英文城市名（备用） |
| myip.ipip.net | 纯中文省市名 |
| whois.pconline.com.cn | 纯中文省市名（GBK） |

合并规则：坐标取优先级最高的可用源，城市显示名优先用中文源（ipip / pconline）。
写入 `location` 为「经度,纬度」（和风支持该格式，最多两位小数），同时记录
`location_source=ip`、`location_ip`、`location_updated`。

⚠️ 定位基于**公网出口 IP**。若机器流量经代理 / VPN（旁路由分流很常见），
不同定位源可能看到不同出口 IP，此时会写入 `location_note` 并在页面上黄色提示，
请核对后到设置页手动改城市。手动改过 `location` 会被标记为 `location_source=manual`。

关闭自动定位：`python3 src/server.py --no-geoip`。

## 缓存与接口调用量

`/api/weather` 走 **stale-while-revalidate**，目标是「打开页面永远不等待」，
同时不额外消耗和风额度：

| 缓存年龄 | 行为 | 上游请求 |
|---|---|---|
| < 10 分钟 | 直接返回缓存 | 0 |
| ≥ 10 分钟 | **先返回旧数据**（`stale=true`），后台刷新一次 | 1 轮（7 个接口） |
| 后台刷新冷却 | 90 秒内多次打开只刷一次；刷新失败则下次打开立即重试 | — |
| 无缓存 / `?fresh=1` | 同步取数 | 1 轮（7 个接口） |

一轮取数 = 实况 + 逐小时 + 逐日 + 空气质量（实时/逐日）+ 生活指数 + 官方预警，共 7 次请求。
这 7 个请求**并发发出**（`QW_MAX_WORKERS=4`），冷启动耗时从约 2.4 s 降到约 1 s。

和风 2025-03 起的计费规则：**每月前 5 万次请求免费**（按自然月累计，不再有「每天 1000 次」），
超出按阶梯价（首档 ¥0.0007/次）计费。按默认配置估算：

| 来源 | 每月请求量 |
|---|---|
| 预警轮询（默认 10 分钟） | ≈4,300 |
| 定时播报（每天 2 次） | ≈420 |
| 页面打开（按需刷新） | ≈2,100（每天 10 次） |
| **合计** | **≈6,800（约占免费额度 14%）** |
